# 官方数据对接说明

> 本文档对应「官方数据包」三份训练包的字段、指标与续训协议。
> 系统代码入口：`run.py --dataset official-a|official-b|official-c`。

## 一、官方包结构（每个包一致）

```
cpu-<x>-<task>-<version>.zip
├── START.md            # 快速开始
├── TASK.md             # 任务与标签说明（= 数据字典）
├── TRAINING_GUIDE.md   # 续训指南
├── training.json       # 基线训练报告（含官方验证指标，用于对照）
├── checkpoint.npz      # 官方预训练权重 + Adam 状态 + 标准化参数（续训起点）
├── history.jsonl       # 基线逐 epoch 记录
├── baseline-info.json  # 包身份与摘要
├── baselines/          # 可修改的模型/训练/预测代码 + 配置 + 测试
└── public/
    ├── train.jsonl     # 训练样本（梯度更新只用它）
    └── validation.jsonl# 公开验证样本（衡量改动，不合并进训练）
```

JSONL 每行：`{"id": ..., "inputs": {...}, "answer": ..., "meta": {...}}`。
`id`/`meta` 仅追溯，不是模型输入；`inputs` 才是预测输入，`answer` 是监督目标。

## 二、三份任务的数据字典

### A · 气体识别（分类）
| 项 | 值 |
|---|---|
| 数据来源 | UCI Gas Sensor Array Drift（#224） |
| 输入 | `inputs.features`，长度 128 |
| 目标 | 6 类：Ethanol / Ethylene / Ammonia / Acetaldehyde / Acetone / Toluene |
| 主指标 | Macro-F1（越高越好）；辅助 Accuracy + 混淆矩阵 |
| 网络 | 128 → 32 tanh → 6 softmax，参数量 4326 |
| 切分 | 公开集：batch 1 = train(445)，batch 2 = validation(1244)；batch 3–10 = 隐藏漂移流 |
| 约束 | 按批次与时间顺序隔离，不随机混合再切分 |

### B · 轴承剩余寿命（回归 RUL，分钟）
| 项 | 值 |
|---|---|
| 数据来源 | XJTU-SY 全寿命振动（25.6 kHz，每分钟一个快照） |
| 输入 | `inputs.features.horizontal`(17) + `inputs.features.vertical`(17) = 34 维 |
| 目标 | RUL_minutes = (N − i) × 1 分钟，最后一条为 0 |
| 主指标 | RMSE（越低越好）；辅助 MAE |
| 网络 | 34 → 24 tanh → 1 线性，参数量 865 |
| 切分 | 按整根轴承分开，train 9 根轴承(7032)，validation 1679 |
| 约束 | 同一轴承不同时间片不得跨集合；目标为确定性剩余寿命，非健康状态分类 |

### C · 发动机剩余寿命（回归 RUL，循环）
| 项 | 值 |
|---|---|
| 数据来源 | NASA C-MAPSS（FD001–FD004） |
| 输入 | `inputs.settings`(3) + `inputs.sensors`(21) = 24 维 |
| 目标 | RUL_cycles = T − t，最后一条为 0 |
| 主指标 | RMSE；辅助 MAE + NASA 非对称分（高估惩罚更大） |
| 网络 | 24 → 32 tanh → 1 线性，参数量 833 |
| 切分 | 按整台发动机分开，train 496 台(113089)，validation 23049 |
| 约束 | 不把发动机编号/循环编号/最终寿命拼为特征；窗口只用当前及过去观测 |

## 三、续训协议（关键）

1. **从随包 checkpoint 继续训练**，不重新初始化：`Model.load(checkpoint.npz)` 恢复
   权重、Adam 一阶/二阶矩、累计步数、随机种子、输入标准化与目标缩放。
2. **只读 public/train.jsonl 做梯度更新**；validation.jsonl 只用于衡量，不进训练集。
3. 可调参数：学习率、批大小、训练轮数；**改 hidden/输入维度/任务 = 需显式权重迁移**，
   不能把新模型声明为原模型续训（参考加载器会拒绝不匹配的 feature/class/hidden）。
4. 预测协议：分类 `outputs:[{label,score}]`；回归 `outputs:{value: 非负}`。
5. 输出目录必须是新目录，不能覆盖上一轮 checkpoint（参考实现用 `xb` 独占写）。

## 四、已发现的不一致（以 TASK.md + configs/*.json 为准）

`B/baselines/README.md` 的配置表仍把 B 写成「三分类健康状态（Normal/Degrading/SevereFault）」，
这是**旧版残留**。当前 B 的 `TASK.md`、`configs/B.json`、`START.md`、`training.json`
均明确 B = **RUL 回归（分钟）**。本系统按后者实现，并在 B 回归路径下不强制 label-provenance。

## 五、对接后的验证结论

- **A 适配器精确复现官方基线**：加载官方 `checkpoint.npz` + 官方 `validation.jsonl`，
  得 macro-F1 = 0.7140，与官方 `training.json` 的 `validation_after.macro_f1 = 0.71403` 一致。
- **B 续训闭环有效**：官方基线 validation RMSE 681.16 → 本系统续训后 586.00（MAE 563.11 → 473.67）。
- 隐藏漂移流（A 的 batch 3–10 等）不在公开包内，正式评测由平台离线喂入，本系统
  `engine/official/loop.py` 按"漂移监测→诊断→续训→上线/回滚→封版"自主运行。

## 七、创新点在官方闭环的落地

全部创新点已接入 `engine/official/loop.py`（复用了同一套 `monitor/diagnose/incident/safety` 模块）：

### 1. 数字孪生仿真场 + 算力双模式

- **无漂移时（hold 窗）**：用漂移算子库合成"未来可能工况"，存入仿真池。
- **检出漂移时**：冻结仿真，算力全部转投续训（不再合成新样本）。
- **关键合规设计**：官方规则明确「梯度更新只用 public/train.jsonl」，因此合成样本
  **只用于候选模型的抗漂移稳健性门槛（gate 的 `sim-robustness`），绝不进入梯度更新**。
  即仿真预演落在「策略层自改进」（评估哪个候选在可能漂移下更稳），而非「模型层自迭代」。
- trace 事件：`simulator/preplay`（合成）、`gate/sim-robustness`（稳健性门槛）。

### 2. 漂移/故障优先级评分 + 故障分类归纳

- 复用 `engine/incident.py`，把每窗可观测信号归入四类：安全 / 系统 / 数据质量 / 性能退化。
- 评分公式 `score = 类别基础分 × 严重度权重 × 强度因子`；安全故障无条件置顶。
- 处置联动：安全故障 critical/high → `halt` 熔断；系统故障 → 把重调参降级为重训压缩预算；
  数据质量 → `quarantine` 隔离该包；性能退化 → 常规续训闭环。
- trace 事件：`incident/assess`（每窗一次），看板/结果里带 `incident` 字段。

### 3. 可解释根因归因 + 漂移前瞻预警

- 监测层输出逐特征**方向语义**（均值上移/下移、方差增大/坍缩、分布形状迁移），
  与误差贡献变化交叉，得到"哪个特征、往哪漂、影响多大"的根因证据链。
- 维护漂移强度序列做线性外推，当前未超阈值但斜率向上时输出 `trend=rising` +
  `eta_windows`，并提前触发低成本重训（`pre-drift`）。
- **官方 C 实测**：W9 由 hold 转为 `pre-drift` 防御，最终 validation RMSE 51.89 / MAE 38.23。

### 4. 安全拒绝机制（SafeGate）

- 三重拒答：输入越界 / 分类置信度不足 / 回归输出越界；拒答样本不参与训练、不污染门槛。
- 官方 C 实测触发 9 次输入越界拒答（跨单元量程差异大），全部留痕 `safety/refusal`。
- 对应赛题安全合规硬要求「须具备拒绝机制」。

### 5. 成本收益自适应预算调度

- 官方闭环的 `action→epochs` 已含漂移严重度，故 `budget_scaler` 在官方侧只保留
  「连续失败加码 + 剩余预算收缩」（`include_severity=False`），避免双重放大导致过拟合。
- 实测：B 的 validation RMSE 从 584.37 → **572.94**，MAE 455.67 → **449.63**；C 无回归。
