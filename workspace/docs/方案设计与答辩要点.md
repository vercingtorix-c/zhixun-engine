# 方案设计与答辩要点

## 一、一句话方案

> **双模式自演化引擎**：无漂移时用「数字孪生仿真场」主动预演未来工况、预免疫模型；
> 检出漂移时冻结仿真、把全部算力转投「五步闭环」完成诊断—调参—上线—回滚/封版。

这是对赛题「无人干预、自我进化」的完整回应：既有**被动进化**（漂移来了能自己恢复），
又有**主动预演**（漂移没来先练兵），同时把**算力预算**做成显式约束，回应"成本控制"。
并落实官方要求的**两层自进化**：模型层自迭代（重训/重调参）+ 策略层自改进
（诊断策略、故障优先级评分、仿真开关与预算分配随反馈自适应调整）。

## 三、为什么这么做（设计论证，答辩可展开）

1. **漂移的本质是"分布的不可逆迁移"**，不是单个坏点。所以监测用三路冗余信号
   （PSI 看输入分布、误差抬升看关系、预测位移看无标签场景），任意单路都不足以定级。
2. **"泛准失效"的根因要分型**：协变量漂移（输入变了）只需量程适配+重训，成本低；
   概念漂移（关系变了）才值得重调参。盲调参要么浪费算力、要么错过真正的根因。
3. **主动预演的收益在"恢复速度"**：评委明确考察"恢复到漂移前 90% 所需步数"。
   预免疫后的模型在真实漂移首窗就已有先验，恢复步数更短——这是本方案最直接的得分点。
4. **算力要显式记账**：每个 trial 估算 GPU 分钟，逐次减半先淘汰再复核，
   白名单拒绝越界配置。决赛会考"算力与预算"，这条是可量化、可答辩的。
5. **换模型要过五道门槛**：工业上"指标好看就上线"会带来稳定性/延迟/安全隐患，
   所以增益、重抽样稳定性、噪声抗干扰、推理延迟、非有限输出比例五项全过才 promote。

## 三·五、故障分级与优先级评分（多突发并发）

工业现场很少"一次只来一种漂移"，常见的是同一时刻多个突发叠加。本方案把信号
先**分类归纳**，再**优先级评分**，按序处置：

| 故障类别 | 含义 | 典型信号 | 基础优先级 | 处置 |
|---|---|---|---|---|
| 安全故障 | 可能伤人/数据/系统 | 输出 NaN/Inf、配置白名单违反、越权访问 | 100（无条件置顶） | 熔断/拒答、冻结上线 |
| 系统故障 | 资源与运行态 | 推理延迟超标、算力预算告急 | 70 | 降级、压缩预算、必要时回退 |
| 数据质量故障 | 数据不可信 | 空跑包、缺失/越界、方差坍缩 | 55 | 隔离该包、不训练 |
| 性能退化 | 模型变差 | 协变量/概念漂移 | 40 | 五步闭环 |

**评分公式**：`score = 类别基础分 × 严重度权重 × 强度因子`；排序规则是
`安全故障优先 → 严重度降序 → 分数降序`。这样当"空跑包 + 延迟飙升 + 强漂移"
同时出现时，系统会先处理延迟（系统故障）与空跑包（数据质量），再去做性能优化，
而不是一上来就花算力调参。每个窗口的故障分级与评分都写进 `trace.jsonl` 的
`incident` 事件，看板"故障分级"列可直接对评委展示。

## 三·六、可解释根因归因 + 漂移前瞻预警

**可解释根因归因**（打"问题诊断与归因"）：监测层不只报"漂了"，还输出逐特征的
**方向语义**——均值上移/下移（疑似增益/量程漂移）、方差增大（疑似噪声/退化）、
方差坍缩（疑似通道失效）、分布形状迁移，并与"该特征对误差贡献的变化"交叉，
得到"哪个传感器、往哪个方向漂、影响多大"的证据链。答辩能把漂移根因讲成故事，
而不是一句"分布变了"。

**前瞻预警**（打"恢复速度"）：维护漂移强度时间序列做线性外推。当前未超阈值但
斜率向上时，输出 `trend=rising` + `eta_windows`（预计几步后超阈值），并提前触发
低成本重训（`pre-drift`）防御——在真漂移临界前就有先验，直接缩短恢复步数。

> 证据：`trace.jsonl` 的 `drift-check` 事件含 `trend/eta_windows/feature_direction`；
> `strategy` 事件出现 `pre-drift` 动作（官方 C 的 W9 已实测触发）。

## 三·七、安全拒绝机制 + 成本收益自适应预算

**安全拒绝机制（SafeGate）**（赛题安全合规硬要求）：赛题明确"须具备拒绝机制"。
本方案做**三重拒答**——输入越界（特征超出参考量程）、置信度不足（分类软概率过低）、
输出越界（回归预测值超出物理量程），拒答留痕可审计。拒绝本身是"拿不准就明确说"，
而不是硬猜一个危险的数。

**成本收益自适应预算**（打"算力与预算/成本论证"）：算力投入与收益挂钩——漂移越
严重、恢复越难（连续失败加码）、预算越宽裕，投入越多；反之收缩。让"花最少的钱换
最大的增益"从口号变成逐窗可计算的缩放因子（`budget_scaler`）。

> 证据：`trace.jsonl` 的 `safety/refusal`、`budget/adaptive` 事件；官方 C 实测触发
> 9 次输入越界拒答、8 次自适应预算。

## 四、评分口径对照（对齐《赛题规则》正式版）

### 客观分（评测平台按步骤自动计算）

官方口径是**单位增益消耗的算力（GPU 时长 / 训练额度）、标注配额、大模型 Token**，
即"花最少的钱换最大的增益"。本方案的落点：

| 官方客观分口径 | 本方案落点 |
|---|---|
| 单位增益消耗的算力 | trial 级成本记账、逐次减半、预算熔断、白名单拒绝越界配置 |
| 标注配额 | 数字孪生预演用合成样本减少对真实标注的依赖；空跑包零标注 |
| 大模型 Token | 传统路线（路线 B）为默认底座，不依赖大模型调参，Token 开销≈0 |

无漂移时零算力、空跑包零算力、只有真漂移才花算力——这是客观分的关键防守点。

### 主观分（评审专家独立打分）

| 主观分维度 | 本方案落点 |
|---|---|
| 方法设计与技术路线 | 五步闭环 + 数字孪生仿真场 + 故障优先级评分 + 可解释根因归因 + 前瞻预警 + 自适应预算，路线 A/B 均可映射 |
| 问题诊断与归因 | 逐特征方向语义（均值/方差位移）+ 误差贡献交叉，得到可讲故事的根因证据链 |
| 实验规范与分析深度 | `trace.jsonl` 全轨迹、逐窗决策链、SwanLab 导出器一键回放云端 |
| 安全可控与工业落地 | SafeGate 三重拒答（越界/低置信/输出越界）+ 白名单 + 熔断 + 回滚 + 哈希链 |
| 报告与答辩 | `dashboard.html` 看板 + `report.md` 复盘 + 三份提交物 |

### 三条基础门槛（不满足即不排名）

| 硬门槛 | 本系统如何满足 |
|---|---|
| 无人工干预完成全部阶段并按时输出 | 评测窗标签不参与决策，闭环全自动，`--seed` 固定即复现 |
| 按《实验记录规范》完整留存记录 | `trace.jsonl` 逐步留痕（配置/种子/预算/得分/耗时/决策理由） |
| 综合性能不低于静态基线 | 内置静态基线对照，同一口径可比，失败可重跑一次取较高分 |

> 注：恢复速度、稳定性、抗干扰等仍作为**内部指标**在 `metrics.py` 与看板中持续跟踪
> （恢复率、稳定期波动、空跑包抗干扰），用于论证方案质量；它们不是官方客观分的直接构成项。

## 五、路线 A/B 的映射（应对"两条路线自由选择"）

- **路线 B（传统持续调优）**是本方案的默认底座：规则化监测 + 规则化诊断 + 逐次减半调参，
  可落地性、可解释性强。
- **路线 A（大模型智能体 Harness）**可通过替换 `diagnose.py` 的决策与 `optimizer.py` 的
  候选生成来实现：把"诊断策略/搜索配置"交给大模型仲裁，工具与实验调度仍走现有 executor。
  本仓库已把决策点收敛成清晰的 `Strategy` 对象，便于无痛替换。

## 六、答辩高频问题预案

- **Q：仿真合成样本会不会带偏模型？**
  A：会做三件事对冲——①合成样本权重低于真实样本（`sim_weight=0.35`）；②只在无漂移时生成，
  且池子有上限；③每个合成场景都带 `reason` 说明，可审计。看板里的"无预演对照"曲线就是消融证据。
- **Q：怎么证明是"无人干预"？**
  A：评测窗标签不参与决策 + `--seed` 固定全流程复现 + `trace.jsonl` 记录每一步。
- **Q：空跑包怎么处理？**
  A：监测阶段识别（有效值占比、方差坍缩、与标签无关联）→ 隔离不入训练 → 模型不塌，
  看板用灰底标出，`metrics` 里有 `empty_packet_delta` 衡量抗干扰。
- **Q：隐藏测试集规模更大、漂移更复杂怎么办？**
  A：逐次减半的预算熔断可扩展到更大窗口；诊断的 `escalate` 会在处置失败后自动扩大搜索，
  不必改代码。决赛数据接入只需实现 `streams.py` 里的一个适配器。
- **Q：成本怎么控制？**
  A：按 `estimate_minutes` 逐 trial 记账，预算耗尽即收敛；无漂移时不调参（零算力），
  空跑包不训练（零算力），只有真漂移才花算力。自适应预算还会按漂移严重度/失败次数/
  剩余预算动态缩放投入，避免"无脑加算力"和"漂移了却舍不得花钱"两个极端。
- **Q：前瞻预警会不会误报、白花算力？**
  A：预警只触发"低成本重训"（`pre-drift`，乘数 0.8 或更低），不是全量调参；且只有
  连续 3 窗以上的强度斜率向上才判 `rising`。即便误报，代价也只有 1~2 个 epoch，
  换来的是真漂移临界前的先验。官方 C 的 W9 已实测触发，属"可解释的保守防御"。
- **Q：拒绝机制会不会影响评测得分？**
  A：拒答只发生在"输入越界/低置信/输出越界"这类本就不该硬猜的样本上，拒绝是
  安全合规要求（不满足即失去资格），且拒答样本不参与训练、不污染上线门槛。
  对正常样本不影响，反而降低隐藏测试集里脏数据带来的塌模型风险。

## 七、已知边界与后续工作

- 分类任务（如 gas）的仿真场只做协变量增强，不臆造标签翻转（见 `simulator.py` 注释）。
- 当前代理模型是"数据驱动的 f(x)"；若官方提供机理方程，可替换为真正物理仿真，
  场景更精确（接口不变）。
- 20 台目标机的规模化与"二次测试方案"：本仓库单机可复现，多机并行只需按窗口分片重放。
